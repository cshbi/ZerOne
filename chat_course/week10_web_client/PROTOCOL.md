# 프로토콜 명세 — 웹/파이썬 클라이언트 공통

이 문서는 **웹 클라이언트가 서버와 주고받는 약속**을 정리한 것입니다.
나중에 **파이썬 클라이언트를 만들 때 이 명세만 그대로 구현**하면 됩니다.
(통로가 WebSocket 이냐 TCP 냐만 다를 뿐, '메시지 약속' 은 우리가 계속 써온 것 그대로)

## 1. 통로 (Transport)
- **웹**: WebSocket 텍스트 프레임 (`ws://localhost:8765`)
- **파이썬(기존)**: TCP 소켓 + 줄바꿈(`\n`) 프레이밍
- 프레임 1개 = '메시지 한 줄' 1개.

## 2. 접속 순서
1. 연결한다.
2. **첫 프레임 = 닉네임(평문)**. 예: `철수`
3. 이후 모든 프레임은 **암호화된 한 줄**(아래 3·4번).

## 3. 암호화 (codec)
- 방식: **AES-256-GCM**
- 열쇠: `SHA-256(공용 암호)` → 32바이트.  공용 암호 = `우리반-공용-비밀열쇠-2026`
- 한 줄 = `base64( nonce(12바이트) + AES_GCM_암호문(암호문+태그) )`
- 파이썬 `codec.py`(AesGcmCodec) 와 브라우저 `codec.js` 가 **완전히 같은 방식**.

## 4. 메시지 포맷 (암호를 풀면 나오는 '한 줄')
파이프(`|`)로 구분:

| 꼬리표 | 형식 | 뜻 |
|--------|------|----|
| `TEXT` | `TEXT\|보낸이\|내용` | 일반 텍스트 (명령도 이걸로 — 내용이 `/` 로 시작) |
| `EMOJI` | `EMOJI\|보낸이\|이름` | 이모티콘 (smile/heart/thumbsup/cry/wow) |
| `FILE` | `FILE\|보낸이\|파일명\|base64` | 파일 |
| `SYS` | `SYS\|시스템\|내용` | 서버 알림 (입장/퇴장/방목록 등) |

## 5. 명령 (클라 → 서버, `TEXT` 로 보냄)
내용이 `/` 로 시작하면 서버가 명령으로 해석합니다.

| 명령 | 하는 일 | 서버 응답 |
|------|---------|-----------|
| `/rooms` | 방 목록 | `SYS ... 방 목록: 잡담(2명), 게임(1명)` |
| `/create 방이름` | 방 만들기 | `SYS ... 방을 만들었습니다: ...` |
| `/join 방이름` | 방 입장 | **최근 대화 5개** → 그다음 `SYS ... 입장했습니다` |
| `/leave` | 방 나가기 | `SYS ... 방에서 나왔습니다` |
| `/who` | 현재 방 멤버 | `SYS ... [방] 멤버: ...` |
| `/rename 새이름` | 닉네임 변경 | `SYS ... 이름을 바꿨습니다` |
| `/w 닉 메시지` | 귓속말 | 대상·나에게만 `TEXT (귓속말)...` |

## 6. 일반 대화 (클라 → 서버)
- 명령이 아니면(내용이 `/` 로 시작 안 하면) **현재 들어가 있는 방** 에 전송.
- 방에 안 들어가 있으면 서버가 `SYS ... 먼저 /join ...` 안내.
- 서버가 `보낸이` 를 접속 닉네임으로 보정한 뒤 그 방 멤버 전원에게 뿌린다.

## 7. 서버 → 클라 (받기)
- 받은 한 줄을 복호화 → 파이프 파싱 → 화면에 표시.
- `보낸이 == 내 닉네임` 이면 '내 말'(오른쪽), 아니면 '남의 말'(왼쪽).

---
### 파이썬 클라이언트 숙제 힌트
`websockets` 라이브러리로 `ws://localhost:8765` 에 붙어서:
1. 첫 줄에 닉네임을 보낸다.
2. 보낼 땐 `codec.py` 의 `AesGcmCodec().encode(...)`, 받을 땐 `.decode(...)` 를 **그대로 재사용**한다.
3. `messages.py` 의 `from_wire` / `to_wire` 도 그대로 재사용한다.
→ 즉 **웹 클라가 한 일을 파이썬으로 옮기는 것**뿐. 서버·코덱·메시지는 건드리지 않는다.
